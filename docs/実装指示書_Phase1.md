## 0. 目的と範囲

MIC の選手・コーチ・保護者が、W杯・世界選手権・五輪以外も含めた大会結果を一か所で見られるリザルトデータベースを作る。
ナショナルチーム用の moguls-results とは別サイトにする（あちらは内部分析を載せる前提で、読者も目的も違う）。
ETL（PDF 読み取り・検証・規則）は moguls-results から複製して共通化し、サイトと公開データだけ分ける。

| 項目 | 決定 |
|---|---|
| 利用者 | MIC の選手・コーチ・保護者。表示モード切替なし。保護者にも分かる言葉で書く |
| 形態 | GitHub Pages 静的サイト。Python ETL が PDF を直接読んで JSON 生成。ログインなし |
| 公開 | 公開リポジトリ `VanWhist/mic-results`、`robots.txt` と `noindex` で検索除外 |
| 対象大会 | 下の第1節の系列すべて。FIS 系海外大会は「日本人選手が1人以上出場した大会」だけ。SAJ の A級・B級公認大会は全部。選考会は結果が公表されたものだけ |
| 対象種目 | モーグル単走は全ラウンド。デュアルモーグルは「順位のみ」の記録として入れる |
| 遡る範囲 | FIS DB と SAJ 競技データバンク（と主催者サイト）で遡れるだけ。上限は棚卸しで確定 |
| 記録の段階 | 明細あり／得点のみ／順位のみ の3段階（第2節）。段階を画面で区別する |
| MIC 選手 | MIC 選手カルテの名簿シートに載っている在籍選手。スナップショットを在籍期間付きで持ち、画面で強調表示する |
| W杯・世界選手権・五輪 | moguls-results の検証済み JSON を「得点のみ」の段階に削って流用する。内部分析（通過ラインとの差、点の経済学）は載せない |
| 元データ | `D:\Claude\ジャッジ分析\全試合のリザルト\`（W杯等、読むだけ）と、新設する `D:\Claude\ジャッジ分析\その他大会のリザルト\`（本 DB 用の PDF 置き場） |
| 見た目 | moguls-results / trampo-results に揃える（css/style.css と js/ui.js の流用） |

## 1. 対象大会の系列

`series` の値と、想定される出典・記録の段階。段階は大会ごとに PDF の中身で決まる（表は見込み）。

| series | 大会 | 出典 | 見込みの段階 | 絞り込み |
|---|---|---|---|---|
| `WC` `WSC` `OWG` | W杯・世界選手権・五輪 | moguls-results の JSON | 得点のみ（削って流用） | 全部 |
| `EC` | ヨーロッパカップ | FIS DB の PDF | 明細あり | 日本人出場分 |
| `NAC` | ノルアムカップ | FIS DB の PDF | 明細あり | 日本人出場分 |
| `ANC` | オーストラリア・ニュージーランドカップ | FIS DB の PDF | 明細あり | 全部 |
| `JWSC` | ジュニア世界選手権 | FIS DB の PDF | 明細あり | 全部 |
| `YOG` | ユースオリンピック | FIS DB の PDF | 明細あり | 全部 |
| `FIS` `NC` `OPN` | 国内 FIS レース（猪苗代・札幌ばんけい・たざわ湖・北塩原など） | FIS DB の PDF | 明細あり | 全部 |
| `SAJ_AJ` | 全日本選手権 | SAJ 競技データバンク／札幌スキー連盟 | 明細あり（2017〜2026 は変換済み） | 全部 |
| `SAJ_AJJR` | 全日本ジュニア | SAJ 競技データバンク／主催者 | 得点のみが多い見込み | 全部 |
| `SAJ_KOKUSPO` | 国スポ（国体） | SAJ 競技データバンク／開催県 | 得点のみが多い見込み | 全部 |
| `SAJ_JOC` | JOC ジュニアオリンピックカップ | SAJ 競技データバンク／主催者 | 得点のみが多い見込み | 全部 |
| `SAJ_A` `SAJ_B` | A級・B級公認大会（地域選手権・地域ジュニアなど） | SAJ 競技データバンク／主催者 | 混在 | 全部 |

- FIS 系の「日本人出場」は FIS DB の大会ページの出場者国籍で判定する。棚卸し（第6節）の一覧に「JPN 出場あり」の列を持つ。
- SAJ の公認等級（A級・B級）は SAJ 競技データバンクの大会情報から取る。等級が分からない大会は棚卸し時に `unknown` として残し、Van さんが判断する。
- デュアルモーグル（`discipline: "DM"`）はどの系列でも順位のみ。

## 2. 記録の3段階（`tier`）

ラウンド単位で決める。1つの大会に段階の違うラウンドが混在してよい。

| tier | 持つもの | 検証の層 | 画面の表示 |
|---|---|---|---|
| `detail` | 順位・得点・タイム・ジャッジ点・ジャンプ・DD・審判名 | 第0〜5層すべて＋ゴールデン＋変異テスト | 「ジャッジ点まで照合済み」 |
| `score` | 順位・得点・タイム・（あれば）ターン点・エア点・タイム点 | 第0層（完全性）・第3層（順位整合）・第4層（横断整合）・第5層（出典照合） | 「得点まで照合済み」 |
| `rank` | 順位・完走区分・（DM は）決勝の対戦相手 | 第0層・第4層・第5層 | 「順位のみ」 |

- `score` の第3層は「得点の高い順に並べて印字の順位と一致」だけ（タイブレークの検算は要素点があるときのみ）。
- `rank` の DM は、ヒート進行（16F-9 のような文字列）は持たない。決勝の最終順位と、記載があれば対戦相手の氏名だけ。
- 段階は PDF の中身から自動判定し（ジャッジ列があれば `detail`）、`etl/expected_rounds.json` の期待値と一致しなければエラー。

## 3. 画面

### ①リザルト（index.html）
- 上部に検索窓（選手名・大会名。漢字・かな・ローマ字の別名で引ける）。候補即時表示 → 選手ページへ。
- 絞り込み: 系列（W杯系／FIS 系／国内）・シーズン・種目（MO／DM）・性別・「MIC 選手が出た大会だけ」。
- 初期表示は「最近の大会」カード。MIC 選手の出場があるカードには印を付ける。
- 大会 → ラウンドを開くと結果表。`detail` は moguls-results と同じ列、`score` は Rank / Bib / Name / 所属 / Time / Turns / Air / Time Pts / Score / Status、`rank` は Rank / Name / 所属 / Status。
- ラウンド見出しに段階のバッジと「公式結果と照合済み」。押すと検証項目一覧・元 PDF・誤り報告リンク。
- 各行から「元 PDF を見る」。
- 狭い画面ではカード表示。

### ②選手（athlete.html?id=XXXX）
- 基本情報（氏名・別名・所属履歴・生年・FIS コード・SAJ 番号・MIC 在籍期間）。
- **キャリア年表**（Phase 1 の主役）: 系列をまたいで新しい順に、大会・ラウンド・順位・得点・出場人数・段階バッジ。シーズンごとに区切る。
- 得点の推移グラフ（`detail` と `score` のラウンドだけ。系列で色分け）。
- 自己ベスト（得点・順位）と、全日本での最高順位。
- `detail` のランは内訳（タイム点・エア・ターン）とジャンプ構成を表示する。moguls-results の「上のラインとの差」「点の経済学」は載せない。
- MIC 選手には上部にバッジ。MIC 以外の選手のページも同じ形で見られる（比較のため）。

### ③大会（event.html?id=XXXX）
- 大会情報（日付・会場・系列・公認等級・種目・ラウンド構成・出典 URL）。
- ラウンドごとの結果表（①と同じ表）。

### ④データについて（about.html）
- 出典、対象大会と絞り込みの規則、3段階の意味、欠測の定義（DNF/DNS/DSQ/RES）、検証の仕組み、データ版・更新日、規則の一覧、誤りの報告先。
- 「この記録はどこまで確かめたか」を保護者向けの言葉で書く。

## 4. データ（`data/`）

数値・ファイル名・manifest の作法は moguls-results と同じ（内容ハッシュ付き、`Math.round(x*100)` の整数演算）。

### events.<hash>.json — 大会 × ラウンド
moguls-results の形に次を足す。
```
{ "event_id": "2025-26-saj-aj-0443",          // season-series-<codex か SAJ 大会ID>
  "series": "SAJ_AJ", "grade": "A" | "B" | null, "discipline": "MO" | "DM",
  "name_ja": "第46回全日本スキー選手権大会フリースタイル競技 MO", "venue": "札幌 ばんけい", "nation": "JPN",
  "format": "saj_q_f_sf" | "saj_q_f" | "wc_traditional" | ... ,   // 進出人数は format 側で持つ
  "rounds": [ { "round_id": "...", "gender": "M", "round": "Q" | "F" | "SF" | ..., "tier": "detail" | "score" | "rank",
                "panel": {"turns": 3, "air": 2} | null, "pace_time": 23.78 | null,
                "source": { "pdf": "SAJ/2026/全日本2026_MO.pdf", "pdf_sha256": "...", "url": "https://sajdb.shikuminet.jp/...", "page": [3,4],
                            "rules_ref": "events/2025-26-saj-aj-0443" }, ... } ] }
```

### runs.<season>.<hash>.json — 1ラン1レコード
moguls-results の形に `tier` を足す。`score` ではジャッジ点の配列を `null`、`rank` では得点も `null`。
DM は `discipline: "DM"`、`rank`、`status`、`opponent`（決勝の対戦相手の athlete_id、無ければ null）だけ。

### athletes.<hash>.json — 選手マスタ
```
{ "athlete_id": "2529645" | "saj-1234567" | "x-yamada-taro-2010",   // FIS コード → SAJ 番号 → 手動 ID の順で決める
  "fis_code": "2529645" | null, "saj_no": "1234567" | null,
  "name": "堀島 行真", "name_latin": "HORISHIMA Ikuma", "aliases": ["ほりしま いくま", ...],
  "affiliation_history": [{"name": "北海道", "club": "...", "from": "2017", "to": "2019"}, ...],
  "yb": 1997, "mic": {"from": "2023-24", "to": null} | null,
  "n_results": 40, "best": {...}, "seasons": [...] }
```
- 同一人物の統合は `etl/athlete_master.json`（人が保守）で行う。FIS コード・SAJ 番号・氏名表記の対応と、統合の根拠（生年・所属）を書く。
- 同姓同名は自動で統合しない。生年か所属で一致しない候補は警告に出し、人が `athlete_master.json` で決める。
- MIC 在籍は `etl/mic_roster.json`（カルテ名簿シートのスナップショット。氏名・athlete_id・在籍期間・取得日）。

### rules/ — 規則
- FIS 系: moguls-results の `rulesets.json`（シーズン版）をそのまま使う。
- SAJ 系: **大会ごとに** `rules/events/<event_id>.json` を持つ。全日本10年分の `規則_YYYY.json` の形式を踏襲し、
  ジャッジ人数・除外の有無・切り捨て桁・ターン下限・エア上限・ペースタイム・タイム点式・進出人数・仮説検定の結果と根拠（要項の記載か、印字からの全件再計算か）を書く。
- 規則は「印字からの全件再計算で確定」する。候補仮説（除外あり／なし、下限の掛け方、丸め）を全件に当て、全件一致した仮説を採用する。複数が一致して区別できないときはその旨を記録する。

## 5. ETL と検証（`etl/`）

`python -m etl.build [--series SAJ_AJ] [--season 2025-26]` の1コマンド。moguls-results の ETL を複製し、取り込み元アダプタを分ける。

```
etl/adapters/fis_pdf/      parser_a.py, parser_b.py   … moguls-results の複製（Q1/Q2 二段、RES、名前の折り返し対応済み）
etl/adapters/fis_dm_pdf/   rank-only                  … DM 決勝の最終順位だけ読む
etl/adapters/saj_aj/       parse_sajmo.py の移植       … 全日本（札幌スキー連盟／SAJ データバンク形式）
etl/adapters/saj_generic/  得点のみ・順位のみの表        … 主催者ごとのレイアウト差は設定ファイル（列の位置・見出し語）で吸収し、無理なものはアダプタを追加
etl/adapters/moguls_results/                           … moguls-results の JSON を score 段階に削って取り込む
```

- 各アダプタは「ラウンド＋ラン配列＋段階」を返す共通の形にそろえ、以降の検証・出力は段階だけを見て動く。
- `detail` は A・B の二重読み取り必須。`score` `rank` は読み取り A だけでよいが、ゴールデン（目視で作った正解）は段階に関係なく大会ごとに数行作る。
- 第5層の照合先: FIS 系は FIS サイト（`fis_fetch.py` 流用、規約により手動実行のみ）、SAJ 系は SAJ 競技データバンクの順位表（HTML があれば）。無い年は `upstream_missing` と明記。
- 公開ゲート・ハッシュ記録・改訂の受け入れ（`--accept-revision`）は moguls-results と同じ。
- 検証レポート（`docs/検証レポート.md`）は系列ごとに節を分け、段階ごとの件数を出す。

## 6. 取得の手順と棚卸し

- FIS サイトの規約により自動取得はしない。SAJ 競技データバンクの利用条件は棚卸しの最初に確認し、同じく手動保存を基本にする。
- PDF の保存はブラウザで行う（Claude in Chrome に操作させてよい）。保存後に SHA-256 を `etl/sources.csv` に記録する（全日本10年分の `出典一覧.md` と同じ列: 年・大会・保存ファイル・URL・取得日・SHA-256・バイト数・備考）。
- **棚卸し（Step 0）の成果物**: `docs/棚卸し_大会一覧.xlsx`。1行＝1大会×性別×種目。列: シーズン・系列・公認等級・大会名・会場・日付・codex または SAJ 大会 ID・種目・性別・ラウンド構成・PDF の有無・ジャッジ明細の有無（段階の見込み）・JPN 出場の有無・出典 URL・備考。
  これで遡れる年と総量を確定し、Van さんが取り込み順を決める。

置き場: `D:\Claude\ジャッジ分析\その他大会のリザルト\<系列>\<シーズン>\<大会>\` に保存。ファイル名は `<大会>_<男子|女子><MO|DM><ラウンド>_<codex か ID>.pdf`。

## 8. 受け入れ基準（Phase 1 完了の条件）

1. 棚卸し一覧があり、対象大会ごとに「取り込み済み／未取得／公表なし」の状態が分かる。
2. 取り込んだ全ラウンドが段階に応じた層で緑。第5層は結果（ok / upstream_missing / skipped）を明記。
3. `detail` のラウンドはゴールデンと A・B の出力が一致し、変異テストで少なくとも1つの層が誤りを止める。
4. `score` `rank` のラウンドもゴールデン（大会ごとに数行）と一致。
5. 選手マスタで、MIC 在籍選手全員が FIS コードまたは SAJ 番号で同定され、同姓同名の未解決警告が 0。
6. 4画面が PC 幅と 390px 幅で横スクロールなしに表示され、JS エラーなし。
7. `README.md` に大会追加の手順（moguls-results と同じ書式）と、段階の説明がある。
8. push 前に Van さんが内容を確認する。

## 9. まだ決めていないこと（棚卸しの結果で決める）

- SAJ 競技データバンクの利用条件（自動取得の可否）と、HTML 順位表の有無（第5層の照合先になるか）。
- 2017 年より前の国内結果がどこにあるか（札幌スキー連盟、各県連、旧 SAJ サイト）。
- 古い年の FIS PDF にジャッジ明細があるか（無ければ `score` 段階で取り込む）。
- 主催者ごとのレイアウトを設定ファイルで吸収できる範囲。無理な大会は個別アダプタか、見送り。
- MIC 名簿の過去在籍者の扱い（在籍期間をどこから取るか。名簿シートに履歴がなければ Van さんが手で補う）。
